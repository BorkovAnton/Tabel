# Исправление зависания (бесконечный спиннер) при входе пользователей с ограниченными правами

## Что исправлено в коде

1. **`frontend/src/auth.js`**
   - Метод `login()` обёрнут в `try/catch`: ошибки корректно логируются и пробрасываются
     компоненту входа, чтобы тот мог остановить спиннер и показать сообщение.
   - Добавлен метод `firstAvailablePage()` — возвращает первую доступную пользователю
     страницу с учётом его `permissions` (для админа и пользователя без прав доступа — `/tabels`).

2. **`frontend/src/views/Login.vue`**
   - Обработчик `doLogin()` имеет полный `try/catch/finally`; в `finally` **гарантированно**
     выполняется `loading.value = false` — спиннер больше не может «зависнуть».
   - Реализован **умный редирект**:
     - если пользователь пришёл на вход с конкретной страницы (`?redirect=...`) и имеет
       на неё права — возврат туда;
     - иначе — переход на первую доступную страницу из `permissions`;
     - если прав нет вообще — показывается понятное сообщение
       («У вашей учетной записи нет доступа ни к одному разделу…») и сессия сбрасывается
       через `auth.logout()`, вместо бесконечной загрузки.

3. **`frontend/src/router/index.js`**
   - В guards роутера (`beforeEach`) исправлен редирект по правам: раньше при недоступности
     целевой страницы выполнялся безусловный переход на первую запись из `permissions`
     (например, на `/`, которая тоже могла быть заблокирована), что приводило к циклу
     редиректов и зависанию. Теперь выбирается первая **реально доступная** страница,
     а если таковой нет — переход остаётся на месте (защита от «пинг-понга»).

## Инструкция по исправлению прав тестового аккаунта в БД

Если у пользователя `Test` в поле `permissions` отсутствуют пути `/` и `/tabels`,
редирект после входа не сможет привести его на рабочую страницу. Выдайте права командой:

```bash
# Выполнить в терминале (из корня проекта, где лежит docker-compose.yml):
docker-compose exec postgres psql -U user -d tabel -c "UPDATE users SET permissions = '[\"/\", \"/tabels\", \"/import\", \"/turnstile-fix\", \"/timesheet-report\"]' WHERE username = 'Test';"
```

После этого **перезалогиньтесь** (или нажмите F5 и войдите заново), чтобы обновлённые
права попали в `localStorage`.

> Примечание: параметр `-U user` соответствует `POSTGRES_USER: user` из `docker-compose.yml`,
> база — `tabel`. Если в вашем окружении другие значения, подставьте их.

## Проверка

Сборка фронтенда выполнена без ошибок:

```bash
cd frontend
npm install
npm run build   # DONE  Build complete.
```

Сценарии, которые теперь работают корректно:
- Неверный логин/пароль → сообщение об ошибке, спиннер остановлен.
- Вход пользователя с ограниченными, но непустыми правами → редирект на первую доступную вкладку.
- Вход пользователя вообще без прав → понятное сообщение + сброс сессии, без зависания.
- Перезагрузка страницы на заблокированной вкладке → редирект на доступную страницу без цикла.
